# dev-flow-agents：统一开发流程总纲

主智能体职责边界：接收需求 → 加载技能/子智能体 → 编排调度 → 消费证据做裁决。
不亲自重新理解一切；通过阶段产物与证据文件判断目标是否达成。

## 五条设计原则（违反任何一条前，先停下来重读）

1. **骨架固定、阶段内动态**：阶段顺序与门禁不可临场发明；阶段内的扇出广度、并行度、重试由数据决定。
2. **验收标准前置冻结**：实现开始前验收标准（AC）已冻结落盘；之后 verifier 只对冻结标准负责，禁止事后放宽。
3. **产物落盘、文件交接**：智能体之间不通过对话内容交接，只通过 `.project/` 下的结构化文件；不落盘的结论视为不存在。
4. **观测契约化、三级缩放**：阶段未完成 = 产物 + STATE.md 更新 + 决策条目三样齐；向人呈报默认一屏摘要，下钻靠链接。
5. **人工门禁少而精**：全流程仅三处等人（见"人工门禁"）；有界修复 3 次超限必须升级，禁止第 4 次尝试时开始糊弄测试。

## 流程总览

```
Triage 分级 ──L0──> 直接执行（STATE.md 记一行即可）
   │ L1/L2
   ▼
理解环：需求澄清 ∥ 现状调查 ∥ 参考调研（并行扇出）
   ▼
🚪 门1：规格与验收标准冻结（等用户批准）
   ▼
设计环：领域建模 + 用户故事 + UML/时序图 → 实现路径 → 垂直切片清单
   ▼
🚪 门2：实现路径确认（等用户批准；L1 可与门1合并为一次确认）
   ▼
增量环（逐切片，敏捷心跳）：
   实现 → 验证(对冻结AC) → 评审(基于diff) → git commit（一片一提交）
        └─ 验证失败 → 有界修复(≤3次) → 超限升级 🚪
   ▼
终评：追溯矩阵核销 + 假设回看 + user story 演示
   ▼
知识同步：文档 / decisions.md / memory / 度量 更新
```

## 第一步：Triage 分级

| 级别 | 判定 | 走法 |
|---|---|---|
| **L0 微改** | 单文件、无接口/数据变化、无新概念（typo、文案、小样式、日志行） | 主智能体直接做；完成后 STATE.md 记一行 |
| **L1 常规** | 一个垂直切片可交付的功能或修复，边界清楚 | 标准环：澄清(轻量) → 现状速查 → 门1(可合并门2) → 增量环(通常 1 片) → 终评(轻量) → 同步 |
| **L2 大特性** | 多切片、跨模块、引入新领域概念、架构影响 | 全流程：理解环三路并行扇出，建模设计完整走 |

拿不准时往高一级靠；如事后降级，在 decisions.md 记录理由。

## 阶段契约

每阶段四要素：目的 / 输入 / 输出（落盘文件）/ 完成定义（DoD）。

### 理解环（M1 起可用）
- **需求澄清**（子智能体 `req-analyst`）：输出 `.project/current/questions.md`、`spec-draft.md`、`assumptions.md`。主智能体随后用 AskUserQuestion 向用户提问（每轮 ≤4 题，最多 2 轮），答案落盘 `answers.md`，最终把规格定稿为 `spec.md`。
- **现状调查**（M2 建 surveyor 智能体；未建前主智能体兼任）：输出 `survey.md` —— 相关模块地图、既有实体清单、约定与坑。
- **参考调研**（M2 建 researcher 智能体）：输出 `research.md` —— 候选方案/库/API 对比，必须带来源链接。
- DoD：产物落盘 + STATE.md 更新 + spec 达到可冻结状态（不存在"答案会改变实现"的未决问题）。

### 设计环（M3）
- 输出：`model.md`（实体/关系/流程，用 Mermaid：ER 图、类图、时序图、流程图）、`user-stories.md`、`plan.md`（垂直切片清单，每片端到端可验证）、`trace-matrix.md`（FR ↔ 切片 ↔ 测试映射，初版）。
- 切片纪律：**垂直不水平**——每片走通"数据 → 逻辑 → 界面/接口"；禁止"先把所有实体写完再写逻辑"式的分层切法。

### 增量环（M2）
- 每片：实现 → 验证（对 spec.md 冻结 AC 逐条给出证据）→ 评审（diff 基础上查"对不对"之外的"好不好"）→ git commit。
- 验证失败：修复重试，**累计 3 次未过必须停下升级**，呈报失败证据与已试方案。

### 终评（每需求一次；L1 轻量）
- trace-matrix 逐行核销；assumptions 逐条回看（仍成立 / 被推翻及后果）；user story 演示（Web 项目用 GUI 测试智能体真实操作一遍）。
- 主智能体裁决"目标是否达成" = 冻结 AC 全部通过 + 矩阵核销完毕 + 抽查关键切片证据。凭证据，不凭感觉。

### 知识同步（M4 完整化；M1 起手动做最小集）
- decisions.md 追加本需求期间的架构/取舍决策；STATE.md 归档该需求；受影响的存量文档更新；跨会话事实写入 memory。

## 观测契约

- **STATE.md 是唯一实时真相**（`.project/STATE.md`）：任何阶段开始/完成/等待/失败，先更新它再继续。宁可写"状态未知"，不可留过时的"一切正常"。
- **产物标准头**（`.project/current/` 下所有产物）：

```yaml
---
stage: 需求澄清
status: draft        # draft | done | waiting-human | failed
inputs: [原始需求.md]
outputs: [questions.md, spec-draft.md]
decisions: 3
---
```

- **三级缩放**：一级 = STATE.md 一屏；二级 = 阶段产物文件；三级 = 工作流日志 / git diff。向用户汇报默认一级，附二级链接。
- **门禁呈报一屏化**：用 `.project/templates/gate-report.md`，决策本身必须 30 秒内可读；超一屏 = 材料不合格，先压缩再呈报。

## 人工门禁（仅三处）

1. **门1 规格冻结**：spec.md + AC 定稿前。呈报：需求理解一句话、AC 列表、开放假设。
2. **门2 路径确认**：plan.md 切片清单拍板前（L1 可与门1合并为一次确认）。
3. **修复超限裁决**：切片验证 3 次未过时。呈报：失败证据、已试方案、候选出路（继续修 / 降级验收 / 人工介入）。

## 智能体索引

模型搭配原则（ADR-007）：强推理给分析与评审、强编码给实现、快模型给高频低风险环节；**实现者与评审官必须跨模型**。模型清单以 ListModels 实时结果为准，变动时只改 agent frontmatter 的 model 字段。

| 角色 | 定义 | 模型搭配 | 状态 |
|---|---|---|---|
| `req-analyst` 需求澄清分析师 | `.zcode/agents/req-analyst.md`（只读 + 产物落盘） | `deepseek-v4-pro`（推理强，歧义识别） | ✅ M1 |
| `surveyor` 现状调查员 | `.zcode/agents/surveyor.md`（只读，产出 survey.md） | `deepseek-flash`（快而便宜，高频调用） | ✅ M2 |
| `researcher` 参考调研员 | `.zcode/agents/researcher.md`（联网抓取，结论必须溯源） | `deepseek-flash` | ✅ M2 |
| `implementer` 实现者 | `.zcode/agents/implementer.md`（一次一片，自测过才交） | `glm-5.3`（编码强） | ✅ M2 |
| `verifier` 验证官 | `.zcode/agents/verifier.md`（逐 AC 留证，结论仅 过/未过/无法验证） | `glm-5.3-flash`（快） | ✅ M2 |
| `reviewer` 评审官 | `.zcode/agents/reviewer.md`（diff 评审 P0/P1/P2，与实现者跨模型） | `deepseek-v4-pro` | ✅ M2 |
| modeler 建模者 / architect 架构者 / doc-syncer 文档员 | 规划中 | 会话默认 | M3–M4 |

未建智能体的阶段由主智能体兼任，按本文件的阶段契约执行，产物同样落盘。
子智能体不直接与用户对话：澄清问题一律由分析师产出 `questions.md`，主智能体统一用 AskUserQuestion 转问。
