# decisions.md —— 架构与取舍决策日志

> 只追加，不改写。每条决策一个 ADR：背景 → 决策 → 后果。编号递增，永不重排。

## ADR-001：阶段产物落盘、文件交接（示例）

- 日期：2026-01-01
- 背景：子智能体之间若靠对话内容传递结论，长会话中会丢失与漂移，且事后无法审计。
- 决策：所有阶段产物写入 `.project/`，交接只认文件；不落盘的结论视为不存在。
- 后果：+ 可审计、可恢复、跨会话可续；− 每阶段多写几个文件（成本可接受）。

## ADR-002：实现者与评审官跨模型（示例）

- 日期：2026-01-02
- 背景：同一模型自审自己的实现，倾向于认可自己的写法，评审形同虚设。
- 决策：`implementer` 与 `reviewer` 必须配置不同的底层模型。
- 后果：+ 评审独立性有机制保证；− 需要维护两个模型的可用性（ListModels 校验）。
